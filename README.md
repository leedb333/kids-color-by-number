# 순서대로 색칠놀이

React + Vite + TypeScript로 만든 어린이용 SVG 색칠 웹앱입니다. 삼성 갤럭시탭 세로 화면을 중심으로, 큰 조작 버튼과 숫자 안내를 제공합니다. 광고·회원가입·결제·분석 SDK·외부 폰트는 없습니다.

## 현재 도안

**실제 사용할 수 있는 도안은 자체 제작한 체험용 SVG 「햇살 아래 작은 꽃」(8색, 25영역) 한 개입니다. 정식 승인 도안이 아닙니다.**

다음 5개 정식 도안은 파일이 아직 제공되지 않아 선택 메뉴만 표시하며 비활성화했습니다. 메뉴의 이모지는 주제 표시이며 실제 도안 이미지가 아닙니다.

| 도안                   | 색상 수 | 상태         |
| ---------------------- | ------- | ------------ |
| 무지개를 바라보는 아이 | 25      | 도안 준비 중 |
| 그네 타는 아이         | 24      | 도안 준비 중 |
| 불을 끄는 소방차 로봇  | 30      | 도안 준비 중 |
| 아기 공룡과 알         | 23      | 도안 준비 중 |
| 꽃밭의 알록달록 나비   | 27      | 도안 준비 중 |

## 개발 및 검증

Node.js 24와 npm을 사용합니다. 기존 체크아웃에서 실행하면 됩니다.

```sh
npm ci
npm run dev
```

Vite 기본 경로는 `/kids-color-by-number/`입니다.

```sh
npm test                 # 순서 제한, 전환, 되돌리기, 저장 데이터 검증
npm run build            # TypeScript 검사 + 프로덕션 빌드
npx playwright install --with-deps chromium
npm run test:e2e          # 프로덕션 preview를 자동 실행하여 터치 브라우저 검증
```

Chromium이 이미 설치된 클라우드 환경에서는 다운로드 대신 아래 명령을 사용할 수 있습니다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

브라우저 테스트는 800×1280 세로 터치 화면과 360px 모바일 화면에서 실행합니다. 순서에 맞는 25개 영역을 실제로 터치하여 완성하고, PNG 시그니처·해상도·노랑 픽셀을 검사합니다. 저장 복원, 색상 경계에서의 되돌리기, 초기화 확인/취소, 확대, 힌트, 키보드 입력, 저장 불가 시 안내, 서비스 워커의 오프라인 재실행도 검증합니다. 실제 갤럭시탭 기기나 Samsung Internet에서의 수동 검증은 별도입니다.

프로덕션 동작은 `npm run build` 후 `npm run preview`로 확인합니다. 서비스 워커는 프로덕션 빌드에서만 등록합니다.

## 사용 방법

- 현재 번호의 미색·점선 테두리 영역을 터치합니다. 다른 번호는 칠해지지 않습니다.
- 현재 색상의 모든 영역을 칠하면 다음 번호로 자동 전환합니다.
- 힌트는 전체 보기로 돌아가 남은 영역 하나를 강조하며 자동으로 칠하지 않습니다.
- 100~300% 확대, 축소, 원래 크기, 스크롤 이동을 지원합니다. 작은 영역은 확대해서 터치하세요.
- 되돌리기는 마지막 한 영역을 취소합니다. 처음부터는 확인 후 진행 기록을 지웁니다.
- 색칠·되돌리기·초기화 시 이 브라우저의 `localStorage`에 즉시 저장합니다. 홈에서 이어할 수 있습니다.
- 모든 영역을 칠하면 축하 효과와 PNG 저장 버튼이 열립니다. 저장 이미지는 가로 1200px이며 번호·힌트 테두리가 없습니다.
- `prefers-reduced-motion` 설정 시 애니메이션을 끕니다. 영역은 키보드 Enter/Space로도 칠할 수 있습니다.

## 정식 도안 추가하기

`src/data/drawings.ts`가 도안 데이터 계약과 카탈로그, 등록 목록입니다. 엔진(`src/engine.ts`)과 UI는 영역의 ID와 색상만 다룹니다.

1. 흑백·컬러 원본을 받은 후, 터치할 각 영역을 **닫힌 SVG path**로 벡터화합니다. PNG/JPEG를 올리는 것만으로는 터치 영역이 생기지 않습니다. 외부 SVG를 직접 HTML로 삽입하지 않습니다.
2. 새 파일(예: `src/data/rainbow-child.ts`)에 `Drawing` 타입의 데이터를 작성합니다. `id`는 카탈로그 ID와 맞추고, 승인된 도안에만 `kind: 'official'`을 지정합니다.
3. `colors`에 번호 순서대로 `{ id, name, hex }`를 정의합니다. `regions`에 `{ id, colorId, d, label: [x, y] }`를 정의합니다. 색마다 적어도 한 영역이 있어야 합니다.
4. 각 `label`은 해당 영역 안의 가려지지 않는 지점에 둡니다. 영역은 겹치지 않도록 만들고, 작은 영역은 확대 상태에서도 터치해 검증합니다. 비색칠 선은 선택 사항인 `decorations`로 분리합니다.
5. `viewBox`에 원본 좌표계를 지정합니다. `drawings`에 등록하면 같은 카탈로그 ID의 메뉴가 활성화됩니다. 홈의 체험용 도안은 따로 유지됩니다.
6. 색상·영역 구성이 바뀌면 `revision`을 올립니다. 저장 키가 `도안 ID + revision`으로 분리되어 예전 영역 ID와 혼동하지 않습니다. 테스트를 추가하고, 실제 터치로 모든 영역을 완성해 확인합니다.

## 로컬 저장과 오프라인 범위

진행 기록은 기기·브라우저·사이트 주소별로 분리됩니다. 서버 전송이나 계정 동기화는 없습니다. 브라우저 데이터 삭제, 비공개 모드 종료, 저장 공간 정리 시 기록이 사라질 수 있습니다. 저장소 사용이 차단되면 안내하고 현재 세션의 색칠은 계속 허용합니다. 잘못된 형식이나 순서의 저장 데이터는 무시합니다.

HTTPS(또는 개발용 localhost)에서 최초 온라인 접속 후 서비스 워커 설치가 끝나 **‘오프라인 준비 완료’**가 표시되면 앱 파일을 캐시에 보관합니다. 이후 오프라인 새로고침·색칠·로컬 저장·PNG 생성이 가능합니다. 첫 방문에는 네트워크가 필요하며, 브라우저가 캐시를 삭제했거나 서비스 워커를 차단한 경우 오프라인 실행을 보장하지 않습니다. 외부 이미지/폰트/API에 의존하지 않습니다. 앱 캐시는 빌드 내용에 따라 갱신하며 다른 사이트의 캐시는 삭제하지 않습니다.

## GitHub Pages

`vite.config.ts`의 `base`, 웹 앱 manifest, 서비스 워커의 범위 모두 `/kids-color-by-number/`에 맞췄습니다.

- PR에서 CI가 단위 테스트·빌드·Chromium 터치 테스트를 실행합니다.
- 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택하세요.
- `main`에 병합하거나 `Deploy GitHub Pages` 워크플로를 수동 실행하면 `dist`를 게시합니다.
- 예상 경로는 `https://leedb333.github.io/kids-color-by-number/`입니다. PR 생성만으로 앱이 배포되지는 않습니다.

이 개발 작업은 별도 브랜치에서 수행하며 자동 병합은 설정하지 않습니다.
