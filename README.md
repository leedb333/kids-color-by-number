# 순서대로 색칠놀이

React + Vite + TypeScript 기반 어린이용 SVG 순서 색칠 앱입니다. 삼성 갤럭시탭 세로 화면과 큰 버튼을 기준으로 만들었습니다. 광고·가입·결제·분석 SDK·외부 폰트는 없습니다.

## 경찰차 로봇 변신 — 28색·135개 독립 영역

최신 main에 업로드된 `public/assets/source/police-car-robot/`의 실제 컬러/흑백 PNG를 추적한 정식 도안입니다. 홈의 경찰차 로봇 메뉴에서 선택합니다. 기존 대표 무지개 도안과 저장 기록은 그대로 유지합니다.

각 경찰차/로봇 면은 별도 ID이며, `colorId`(순서)와 `fill`(실제 색상)을 각각 명시합니다. 한 번 터치하면 해당 면 하나만 채워지고, 같은 번호의 다른 면은 바뀌지 않습니다. 해당 번호의 모든 필수 면을 따로 칠해야 다음 번호로 전환합니다. 배경과 윤곽을 포함한 실제 SVG 평면색은 정확히 28개이며 모든 번호가 필수 영역에 사용됩니다.

49개 얇은 흰자·하이라이트·미세 연결선/틈은 고정 흑백 장식으로 보존합니다. 다른 면에 묶어 자동 채색하지 않습니다. 작은 필수 면은 힌트를 누르면 해당 위치로 자동 확대/이동하며 이 도안만 최대 1600%까지 확대할 수 있습니다. 완성 PNG는 1200×1499입니다. PNG의 경계 안티앨리어싱 RGB 중간값은 별도 퍼즐 색상이 아닙니다.

## 첫 번째 정식 퍼즐

**「무지개를 바라보는 아이」 — 25색, 37개 터치 영역**을 홈의 대표 도안으로 제공합니다.

`public/assets/source/rainbow-child/rainbow-kid-line.png`의 닫힌 영역과 검은 윤곽을 직접 추적한 SVG입니다. 얼굴/눈/입/머리카락의 비율, 우비 외곽·단추·주머니, 장화, 나무, 그네, 미끄럼틀, 구름·무지개, 물웅덩이의 위치는 원본 흑백 도안을 따릅니다. 새로 상상해 그린 실루엣이나 PNG 배경 위의 투명 터치 영역을 사용하지 않습니다. 실제 화면과 PNG 출력 모두 벡터 path로 구성됩니다.

컬러 원본 `rainbow-kid-color.png`에서 색상을 추출해 25색 순서를 유지합니다. 원본 그라데이션과 반사광은 평면 25색으로 단순화합니다. 원본의 225개 닫힌 공간을 37개 목표로 묶어, 눈의 흰자·작은 꽃잎·단추·밑창·가는 기둥에 따로 작은 번호를 붙이지 않습니다. 작은 세부 영역은 주변의 큰 목표와 함께 해당 색상으로 채워집니다. 미끄럼틀 안쪽은 마지막 25번 목표입니다.

새 도안은 `revision: 2`입니다. 영역/색상 구성이 달라졌으므로 revision 1의 진행 상태를 잘못 재생하지 않고 새 기록으로 시작합니다. 이전 기록은 지우지 않습니다. 새 도안의 자동 저장·이어하기·되돌리기·초기화는 그대로 동작합니다.

기존 체험용 꽃 도안은 `src/data/test-flower.ts`에 개발/회귀 테스트용으로 보관하며 홈과 정식 카탈로그에서는 숨겼습니다. 예전 체험 기록을 삭제하지 않고 정식 도안의 진행 상태와 분리합니다.

## 참고 원본과 재현 가능한 추적

두 원본 PNG는 저장소에 있으며 수정하지 않았습니다. 크기는 각각 800×999입니다. `public/assets/source/rainbow-child/sources.json`과 `src/data/rainbow-child/trace-manifest.json`에 파일 이름·크기·SHA-256을 기록하고 테스트에서 원본 일치를 검사합니다.

[원본 폴더 설명](public/assets/source/rainbow-child/README.md)과 [추적 도구 사용법](scripts/rainbow-trace/README.md)을 참고하세요. 추적용 Python 도구는 개발 시에만 사용하며 앱/일반 빌드/CI에는 필요하지 않습니다. 기존 원본을 덮어쓰지 않는 복사 도구 `scripts/import-rainbow-sources.mjs`의 파일 이름도 실제 원본 이름과 맞췄습니다.

## 개발 및 검증

Node.js 24와 npm을 사용합니다. 기존 체크아웃에서 실행합니다.

```sh
npm ci
npm run dev
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

브라우저 다운로드가 제한되어도 시스템 Chromium이 있으면 다음과 같이 실행할 수 있습니다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

프로덕션 동작은 `npm run build` 후 `npm run preview`로 확인합니다. 서비스 워커는 프로덕션에서만 등록합니다. Vite 기본 경로는 `/kids-color-by-number/`입니다.

단위 테스트는 색상 순서, 자동 전환, 되돌리기, 저장 데이터 검증, 25색 도안 계약·원본 해시·225개 공간의 그룹 배정·원본 복사 스크립트를 검사합니다. Playwright는 800×1280 터치 화면과 360px 모바일 화면에서 37개 영역을 실제로 터치해 완성합니다. 저장/이어하기, 강조/힌트, 확대, 초기화 확인/취소, 키보드 입력, 25색 팔레트 자동 스크롤, PNG 파일/해상도/색상 픽셀, 오프라인 재실행, revision 1 기록의 보존도 검증합니다. 추가로 원본 PNG의 검은 윤곽과 SVG 윤곽을 래스터화해 직접 IoU > 90%, 원본 윤곽의 1픽셀 이내 재현율 > 99.5%를 검사합니다. 이 수치는 윤곽의 일치도이며 원본의 색상/명암 전체가 같다는 뜻은 아닙니다. 실제 갤럭시탭/Samsung Internet의 수동 검증은 별도입니다.

## 도안 데이터 구조

- `src/data/types.ts`: `Drawing`, `Region`, `PaintColor` 계약
- `src/data/drawings.ts`: 정식 카탈로그, 등록 목록, 대표 도안
- `src/data/rainbow-child/palette.ts`: 한글 색상 이름·HEX·1~25 순서
- `src/data/rainbow-child/regions.ts`: 닫힌 path·영역 ID·색상 번호·숫자 좌표
- `src/data/rainbow-child/index.ts`: 제목·viewBox·revision 및 도안 조립
- `src/data/rainbow-child/outline.ts`: 원본에서 추적한 검은 윤곽의 베지어 path
- `src/data/rainbow-child/decorations.ts`: 큰 목표와 함께 칠하는 작은 세부 요소
- `src/data/rainbow-child/trace-manifest.json`: 출처 해시·원본 영역 배정·라벨 안전 여백
- `src/Artwork.tsx`: 공통 SVG 렌더러와 영역별 터치/키보드 입력
- `src/engine.ts`: 순서 제한·진행 상태·저장 검증

새 정식 도안은 같은 형식의 폴더에 작성하고 카탈로그 ID로 `drawings`에 등록합니다. `featuredDrawing`을 바꾸면 홈 대표 도안도 교체할 수 있습니다. 색상마다 한 영역 이상이 있어야 하며 `colors`는 번호 순으로 정렬합니다. 닫힌 영역을 만들고 숫자를 실제로 보이는 내부에 둔 뒤 모든 영역을 터치해 검증하세요. 번호와 가는 장식은 별도 터치 대상을 만들지 않습니다. `paintWith` 장식은 지정한 영역을 칠한 후 나타나는 색상 세부 요소이며 자체 목표가 아닙니다. `outlinePath`는 장식 위에 표시하는 원본 윤곽, `fillRule: evenodd`는 흰자/속 공간 같은 구멍을 보존합니다.

기존 정식 도안의 영역 구성이 바뀌면 `revision`을 올립니다. 저장 키가 도안 ID와 revision으로 분리되어 이전 좌표/ID를 잘못 복원하지 않습니다.

## 기능과 로컬 저장

현재 색상의 영역은 미색·점선 테두리로 표시하고 다른 번호의 터치를 거절합니다. 힌트는 남은 영역 하나를 강조하며 전체 보기로 돌아갑니다. 기본 100~300% 확대(경찰차 로봇은 최대 1600%)와 스크롤 이동, 한 영역씩 되돌리기, 확인 후 초기화를 지원합니다. 팔레트는 현재 색상으로 자동 스크롤되지만 순서를 임의로 건너뛸 수 없습니다.

색칠·되돌리기·초기화는 이 브라우저의 `localStorage`에 즉시 저장합니다. 기기/브라우저/사이트 주소에 따라 기록이 분리되며 서버 전송이나 계정 동기화는 없습니다. 브라우저 데이터 삭제/비공개 모드 종료/저장 공간 정리 시 기록이 사라질 수 있습니다. 저장 차단 시 안내하고 현재 세션의 색칠은 계속 허용합니다. 잘못된 저장 데이터는 무시합니다.

완성 시 축하 효과와 **1200×1499 PNG** 저장을 제공합니다. PNG에는 번호/힌트 테두리가 없고 얼굴 등 장식은 포함됩니다. `prefers-reduced-motion`이면 애니메이션을 끄고 Enter/Space로 영역을 칠할 수도 있습니다.

## 오프라인과 GitHub Pages

최초 온라인 접속 후 ‘오프라인 준비 완료’가 나타나면, 캐시된 앱과 번들에 들어 있는 SVG 데이터로 오프라인 새로고침·색칠·로컬 저장·PNG 생성을 지원합니다. 외부 이미지/API 없이 실행됩니다. 원본 PNG는 참고/보관 자료로, 필수 오프라인 캐시에 넣지 않습니다. 첫 방문/브라우저 캐시 삭제/서비스 워커 차단 상태에서는 오프라인 실행을 보장하지 않습니다.

`base`, manifest, 서비스 워커 범위는 모두 `/kids-color-by-number/`를 유지합니다.

1. 이 기능 브랜치의 PR을 검토해 `main`으로 병합합니다. 자동 병합은 하지 않습니다.
2. 저장소 Settings → Pages의 Source가 **GitHub Actions**인지 확인합니다.
3. `Deploy GitHub Pages` 워크플로가 새 `dist`를 게시합니다. 필요하면 수동 실행할 수 있습니다.
4. 게시 후 `https://leedb333.github.io/kids-color-by-number/`에서 확인합니다. 기존 탭은 닫았다 다시 열어 새 서비스 워커가 활성화되도록 합니다. 색칠 기록을 유지하려면 사이트 데이터를 삭제하지 마세요.

브랜치 업로드나 로컬 빌드는 실제 Pages 배포 완료를 의미하지 않습니다.
